## Outcome
- **Verdict:** clean deploys; the feature needed two follow-ups to actually work.
- **What broke:** nothing user-visible. Twice, however, a deploy succeeded with
  health green while the feature did nothing:

  1. The mirror synced 1595 calendar entries carrying 1595 iCalUIDs and indexed
     **none** of them. The code read `upsert(...).execute().data`, and PostgREST
     returns no representation for that upsert, so the loop ran over an empty
     list. Fixed in 5d8fb136 by reading the rows back.
  2. That fix indexed only what a pass writes. Once a sync token exists an
     unchanged calendar returns no rows, so the 1595 already-mirrored entries
     would have stayed unindexed for good. Fixed in c4ad7329 by making indexing
     a repair that runs every pass and converges.
  3. The repair then failed on every row with SQLSTATE 42P10, "there is no
     unique or exclusion constraint matching the ON CONFLICT specification".
     20260903000001 had created the hint index partial, and PostgreSQL cannot
     infer a partial unique index from an ON CONFLICT target unless the
     statement repeats the predicate, which PostgREST cannot express. The
     predicate was never needed: NULL is distinct from NULL in a unique index,
     so a plain index constrains calendar-entry hints while leaving event hints
     unconstrained. Fixed by 20260904000001 and deployed as b251e02f.

     This one failed quietly because the caller logs and continues — a hint that
     fails to store costs a match, not a wrong one. Correct for a single entry,
     and it hid a total outage of the feature.

- **Which gate should have caught it:** none could, and that is the finding.
  Every test covers the row mapping and the runtime wiring; neither can see what
  the database hands back, which is exactly where both bugs lived. The only
  thing that caught them was querying production's tables after deploying —
  the observation windows this log exists for.
- **Gate change made as a result:** two tests now pin the failing shapes
  directly — an upsert that echoes nothing must still produce a hint, and an
  unchanged calendar must still converge to a full index.
