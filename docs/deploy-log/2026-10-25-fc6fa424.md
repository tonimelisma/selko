### What it fixes
Four active, Google-synced copies of one 8am school parade sat on one user's
Fri 2026-10-30 morning. `llm_call_log` traces showed three causes:

1. The compare prompt showed the extracted event local (`08:00-07:00`) beside
   stored rows in UTC (`15:00+00:00`); the model called the same instant "a
   different time slot" (trace `063e0b9d`). All times now render as local
   wall-clock in the user's zone.
2. Candidates repeated: each synced Selko event appeared as the row and again
   as its own mirrored provider entry; a shared-calendar recurring event three
   times (21 candidates for one morning). `_collapse_candidates` keeps one per
   real event.
3. A match on a spouse's **shared** calendar entry was adopted; the worker
   could not find that id on the user's write calendar and created a new
   event. A mirror-only `gcal:` match is now an audited no-op
   (`EventMatch.on_other_calendar`).
