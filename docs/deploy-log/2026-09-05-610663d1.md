## Outcome
- **Verdict:** clean
- **What broke:** nothing in this deploy. It also incidentally recovered a
  pre-existing degraded ingestion state (see above).
- **Which gate should have caught it:** the History bug itself was catchable and
  is now caught. The frontend lane could not see it because
  `email-history.test.js` stubs `supabase.from` wholesale, so the select string
  was only ever asserted against itself — green by construction after the column
  it names is dropped.
- **Gate change made as a result:**
  `backend/tests/integration/test_schema_contract.py::test_frontend_select_columns_exist_in_the_live_schema`
  (in 610663d1). It parses every frontend PostgREST select string, attributes
  each `.select()` to the nearest preceding `.from()` (resolving module constants
  such as `EVENT_RELATIONS`), and checks each referenced table and column against
  the live schema. Verified to go red on the exact defect before being trusted.
  The parser raises on a select token it cannot read rather than skipping it, so
  coverage cannot silently shrink.

## Follow-ups
- The ingestion runtime was dead in production for an unknown period while
  `/health` reported `degraded` for a reason no alert acted on. A restart fixed
  it; nothing detected it. Worth asking what makes ingestion liveness
  self-healing rather than restart-dependent.
- Graph egress resolved as predicted. Between T+0 (81 s, 11.47 MB) and T+15m
  (921 s, 11.63 MB) only 154 KB moved -- ~183 B/s steady state, ~0.5 GB/30d.
  The T+0 projection of ~369 GB/30d was an artefact of extrapolating the
  post-restart Outlook catch-up; `projected_bytes_per_30d` is not meaningful
  until uptime greatly exceeds the catch-up window, which is worth remembering
  before anyone reacts to that field again.
- **Unrelated defect found while the deploy was being watched**, filed from this
  session rather than fixed here: `emails.py` discards `body_html`, and
  `event_processing.py:418` selects `body_text or snippet` by truthiness. A
  Ticketmaster message whose `text/plain` part is the single stub word
  "Ticketmaster" therefore reached the LLM as 14 characters and returned
  `no_event`; the real content was in the discarded HTML part. Not caused by
  this deploy -- it processed at T+0 only because the restart drained the
  backlog.
